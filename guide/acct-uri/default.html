acct-URI explained for ActivityPub developers

Fediverse ID → acct-URI → WebFinger

by Charles Iliya Krempeaux

ActivityPub developer use other protocols, formats, and technologies in addition to ActivityPub. One of these is — the acct-URI.

A Fediverse ID will get transformed into an acct-URI before it is passed to WebFinger.

The purpose of acct-URI is to have a way of representing a user account as a URI. Because WebFinger expects the things (the resource) you give it to be a URL/URI/IRI.

A Fediverse ID is not a URI, so we transform it into a URI by turning it into a acct-URI. For example, the Fediverse ID @reiver@mastodon.social becomes the acct-URI acct:reiver@mastodon.social.

acct-URI Structure

acct-URI are made up of 5 parts — with 2 parts that you actually care about.

The user-part and the host of the acct-URI are the important parts.

acct-URI Scheme

Note that acct-URI schemes are case-insensitive (because all URI schemes are case-insensitive).

So, these are all equivalent:

  • acct:reiver@mastodon.social
  • accT:reiver@mastodon.social
  • acCt:reiver@mastodon.social
  • acCT:reiver@mastodon.social
  • aCct:reiver@mastodon.social
  • aCcT:reiver@mastodon.social
  • aCCt:reiver@mastodon.social
  • aCCT:reiver@mastodon.social
  • Acct:reiver@mastodon.social
  • AccT:reiver@mastodon.social
  • AcCt:reiver@mastodon.social
  • AcCT:reiver@mastodon.social
  • ACct:reiver@mastodon.social
  • ACcT:reiver@mastodon.social
  • ACCt:reiver@mastodon.social
  • ACCT:reiver@mastodon.social

If you are implementing the server-side of WebFinger, you should probably normalize the scheme of the URL/URI/IRI you received as the resource by making the scheme lower-case.

Also, if you are implementing the client-side of WebFinger, you should probably normalize the scheme of the URL/URI/IRI you are sending as the resource by making the scheme lower-case.

(Note that you need to be careful about lower-casing the scheme of an acct-URI, since some parts of a acct-URI is case-insensitive but other parts are case-sensitive. I.e., you cannot validly lower-case the whole acct-URI.)

acct-URI Host

Note that acct-URI hosts are case-insensitive (because all hosts are case-insensitive).

So, these are all equivalent:

  • acct:reiver@mastodon.social
  • acct:reiver@MASTODON.SOCIAL
  • acct:reiver@mastodon.SOCIAL
  • acct:reiver@MASTODON.social
  • acct:reiver@MaStOdOn.SoCiAl
  • acct:reiver@mAsToDoN.sOcIaL
  • etc

If you are implementing the server-side of WebFinger, you should probably normalize the scheme of the host of the acct-URI you received as the resource by making the host lower-case.

Also, if you are implementing the client-side of WebFinger, you should probably normalize the host of the acct-URI you are sending as the resource by making the host lower-case.

(Note that you need to be careful about lower-casing the host of an acct-URI, since some parts of a acct-URI is case-insensitive but other parts are case-sensitive. I.e., you cannot validly lower-case the whole acct-URI.)
