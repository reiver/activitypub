xsd:nonNegativeInteger

n ∈ ℕ0

by Charles Iliya Krempeaux

Some ActivityPub properties have a type of xsd:nonNegativeInteger. For example: height, startIndex, totalItems, width.

For example, you may have seen ActivityPub

As the name suggests, xsd:nonNegativeInteger represents a non-negative integers. I.e., here are some xsd:nonNegativeInteger:

  • 0
  • 5
  • 123
  • 170141183460469231731687303715884105727

But, also these, too, are also some xsd:nonNegativeInteger:

  • 0000
  • +5
  • 0000123
  • +00005678

So, xsd:nonNegativeInteger includes things you probably expect — such as 0, 5, and 123.

But, xsd:nonNegativeInteger also includes some things that, while are correct from a mathematical radix representation point of view, may be things that you might not expect — such as 0000, +5, 0000123, and +00005678.

And then there is: 170141183460469231731687303715884105727. Which, at first sight might be something you expect, but — some might notice that it is much larger than the biggest 64-bit unsignedinteger. I.e., 170141183460469231731687303715884105727 is bigger than:

So, xsd:nonNegativeInteger has some quirks — from the point of view of someone who is used to working with 64-bit unsigned integers, or 2048-bit unsigned integers, or whatever. These quirks would affect how you represent, store, parse, and validate a xsd:nonNegativeInteger.

That means that technically, you should NOT store xsd:nonNegativeInteger in 64-bit unsigned integers. (In Golang, the built-in type for a 64-bit unsigned integer is uint64 — but don't use that.)

(Although practically, you might not ever see a number larger than 18,446,744,073,709,551,615 = 264 - 1. So, although it is technically incorrect "wrong" to store a xsd:nonNegativeInteger in a 64-bit unsigned integers, you might be able to get away with it. But, it you do that, you should validate and do error check in case you get an overflow.)

If you want to be technically correct, you should either store the xsd:nonNegativeInteger as a raw string, or store it a variable length (big) integer. (In Golang, there is the big.Int type that could be used. Althogh you could also create something yourself from scatch.)

Multiple Representations

Here is one quirk of xsd:nonNegativeInteger — there are multiple valid ways to represent the same number using xsd:nonNegativeInteger.

(Although, to be fair, this is true of mathematical radix representation in general. But, it could surprise some people who perhaps don't expect it. So, we will discuss it.)

Example: Multiple Representations of Zero

For example, all of these values are valid values for xsd:nonNegativeInteger for the number zero (0):

  • 0
  • 00
  • 000
  • 0000
  • 00000
  • +0
  • +00
  • +000
  • +0000
  • +00000

Note that xsd:nonNegativeInteger has a concept of a canonical representation. That even though xsd:nonNegativeInteger has multiple representations for a number, that there is only one canonical representation. For this particular example, the xsd:nonNegativeInteger canonical representation is :

  • 0

Optional Preceding Plus Sign

Note that xsd:nonNegativeInteger allows an optional preceding plus sign (“+”) (U+002B).

Although a xsd:nonNegativeInteger in its canonical representation does not allow for a preceding plus sign (“+”) (U+002B).

Optioanl Leanding Zeros

Here is one quirk of xsd:nonNegativeInteger — xsd:nonNegativeInteger allows an optional leading zeros (“0”) (U+0030).

Although a xsd:nonNegativeInteger in its canonical representation does not allow for leading zeros (“0”) (U+0030).

No Maximum

Also note that xsd:nonNegativeInteger does not have an upper bound — does not have a maximum value.

Meaning, xsd:nonNegativeInteger can be larger than a unsigned 64-bit integer (uint64) can hold. It can even larger than a unsigned 128-bit integer (uint128), unsigned 256-bit integer (uint256), unsigned 512-bit integer (uint512), unsigned 1024-bit integer (uint1024), unsigned 2048-bit integer (uint20248), etc, can hold.

Canonical Representation Example

xsd:nonNegativeInteger has a concept of a canonical representation.

Some numbers can be represented in more than one way as a xsd:nonNegativeInteger. For example, all of these represent the same number:

  • 12345
  • 012345
  • 0012345
  • 00012345
  • 000012345
  • 0000012345
  • 00000012345
  • 00000000000000000000000000000012345
  • +12345
  • +012345
  • +0012345
  • +00012345
  • +000012345
  • +0000012345
  • +00000012345
  • +00000000000000000000000000000012345

The canonical representation of all these is:

  • 12345

Canonical Representation

The canonical representation of an xsd:nonNegativeInteger has the following properties:

  • Does not have optional preceding plus sign (“+”) (U+002B).
  • Does not have leading zeros.
